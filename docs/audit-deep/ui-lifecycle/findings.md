## Findings and decisions

### UI-1 — Closed captions disappear into retained, unrendered detail state

Severity high for hearing accessibility; source-confirmed integration gap. Audio captions are pumped at Core/Session/RunSession.Audio.cs:56 and retained at :163-169. CombinedSystemStatusLines appends them at RunSession.StatusLines.cs:44-45. Game/SessionUiBridge.cs:136 sends those lines to ObjectiveChip.SetSystemStatusLines (:72-76). ObjectiveChip.Refresh (:141-145) renders only objective/progress; caption text is available only through GetDetailLines/GetHudText (:114-127), with no production consumer found for that chip detail surface. LastCaptionLine (:RunSession.cs:532) likewise has no production rendering caller. Thus player enables captions, encounters fire/threat sound, router emits a caption, but normal HUD never displays it. Expected: a visible caption channel with duration and semantic sound identity. Adapt existing router/model and add a dedicated consumer; retain bus controls. Verify caption visibility during simultaneous alerts and 2x text. No runtime accessibility pass claimed.

### UI-2 — Difficulty settings and New Run difficulty diverge

Severity medium for settings meaning, high for offered launch choices; source-confirmed. MenuCoordinator:731/:790 changes SettingsState only. Actual run modifiers derive from RunSession.RunContext.cs:52-54 and Launch.DifficultyId (Game/PlayableBootstrap:181). TitleScreen.OpenNewRunSetup:265 deliberately seeds SliceDifficultyId rather than stored preference; FrontEndPlayModeTests.NewRunSetupIgnoresPersistedNonSliceDifficulty (:287-308) explicitly requires this. The RememberNewRunDifficulty comment (:307-314) is stale, not proof of intended arbitrary New Run support. More serious: NewRunSetupPanel loads all 3 biomes and 3 difficulties and permits arbitrary/random seed, while PlayableBootstrap:112-116 invokes Core/Procgen/MilestoneALaunch.TryAccept (:26-38), accepting ONLY seed 17, breach_field, standard unless a layout override is supplied. Changing any offered selector can return a failed launch to Title. FrontEndPlayModeTests stubs TitleScreen.SceneLoader (:48-52), so request-generation passes do not establish playable launch. Expected: show supported choices and accurately label immutable run difficulty. Adapt by disabling unsupported selectors or implementing their actual launch contract; do not merely seed stored hardened preference, which would fail the current gate. Retain explicit fail-closed layout identity.

### UI-3 — Low Oxygen tutorial is persistent history presented like a current warning

Severity medium; source-confirmed static sequence, screenshot cause unverified. RunSession.Hazards.cs:192-194 triggers oxygen_low at the OxygenState safe threshold. TutorialState.Trigger:94-104 stores fired/latest once; HasPendingBanner:139-143 tests only dismissal. GetSummary/ApplySummary preserve latest, fired, dismissed (:182 onward). MenuCoordinator:1131-1134 shows latest pending text, without checking recovered oxygen. A model sequence of low oxygen -> Trigger -> recover to 100 -> HasPendingBanner remains true follows directly from these independent state machines. Another tutorial overwrites latest; this is one latest slot, not FIFO notification queue. Expected: clearly distinguish tutorial instructions/history from live danger; adapt presentation or clear condition-dependent warning. Retain one-shot codex unlock history. This makes the retained screenshot plausible but does not establish its causal history.

### UI-4 — Audio service retains old session models across scene boundaries

Severity medium; static integration risk. AppServices.Ensure:56-60 persists service; Compose:90-94 parents AudioManager beneath it. RunSessionHost.Boot:161-163 binds MusicGainSource/AmbientSource to session models. AudioManager:411-414 stores them, and looping stems/beds start at :417-443/:490. Host teardown:626-636 and RunSession.Dispose (Build.cs:466-482) do not unbind models or stop voices/stems/beds. TitleScreen does not bind a title model or stop previous run audio. Therefore old session music/ambient model references remain and looping sources retain previous gains into Title until a later session replaces them. More specifically, Title scene's camera has only Transform, Camera and URP additional data (Assets/Scenes/Title.unity:198-200), no serialized AudioListener; no App production code composes a title listener. AudioManager.UpdateListenerTransform:340-348 creates one only beneath a player anchor, destroyed on leaving Playable. Static risk is silent title UI plus retained old audio state, not established audible carry-over in Title. Adapt an explicit title listener and end-session/reset transition; retain single process-wide audio service and preferences. Verify listener count on first Title and return Title, then Title -> run -> title -> run plus save reload timing.

### UI-5 — Unbounded visited-state traversal and snapshot growth

Severity medium for long-haul scaling; source-confirmed complexity, performance magnitude unverified. AllKnownShips (RunSession.Ships.cs:1096-1112) allocates list/hash and walks all VisitedShips. TickPresentShips (RunSession.Tick.cs:134-136) invokes that every simulation frame and allocates another hash. Ordinary departed wreck geometry is freed (Travel.cs:228-231/:298-301), so this is not evidence all visited Unity geometry stays resident. Piloted/home members are retained intentionally. WorldSnapshotAssembler:288-294 materializes every visited GetSummary, except restricted demo pruning; SynapticSeaWorld:111-115 saves all GeneratedMarkerIds. No eviction/partition boundary found on this path. N visits therefore increase every-frame registry scanning and full snapshot data, even when most roots are absent. Expected: world conservation with bounded active working set and partitioned persistence. Adapt registry/cache/snapshot locality; never simply erase visited state. Verify 10/100/1000 deterministic visits, retained root counts, save size/latency and memory separately.

### UI-6 — Absent ship simulation silently drops gaps above 30 minutes

Severity medium, design decision requiring verification. ShipRuntime.CatchUp:210-228 caps elapsed time at MAX_CATCHUP_SECONDS=1800 (:53), then sets LastSimTime to current worldTime (:217) before substeps. ShipInstance LastSimTime persists (:198-199/:295); reboarding calls CatchUpShip at Travel:57. Journey: depart ship for multiple hours -> return -> systems/web/hull advance only 30 minutes while timestamp discards remainder. Expected persistent survival behavior must define background decay, not assume unlimited full simulation. Adapt analytic/partitioned catch-up or document deliberate cap. Retain bounded substeps for numerical stability. This catch-up covers systems + web/hull, not all room fire/production subsystems (ShipRuntime:135-154).

### UI-7 — New owned shelter cannot inherit original-home production role

Severity high for persistent-home journey; source-confirmed authority boundary. BuildCraftingStations (RunSession.Crafting.cs:200) and BuildProductionStations (:270) return when AwayFromStart. Stations parent to HomeShip (:223/:308). Production power callback reads coordinator PowerGridState allocation (:284-286); expanded systems in Ships.cs:90 onward remain coordinator home models. Save stores hydroponics/water summaries as top-level run fields (RunSnapshotAssembler:96-99), not per-ship production owners. A repaired, claimed and breathable wreck can be a recovery habitat (Hazards.cs:242-259) yet does not become production home authority. Expected: selected owned habitat has explicit services/station/storage ownership. Adapt ownership before moving UI labels alone. Retain portable wound treatment: Wounds.cs:91-135 reads player inventory and wound state without original-home restriction. Storage inventories exist per ShipInstance; do not report all inventory as home-only.

### UI-8 — Enabled controls overstate their current reach

Severity low/medium. AudioSettings Voice log toggle is inert as above. Language selector is persisted English-only and UI strings stay literal. Player maps have no rebinding settings or binding-save surface. Some inspection shortcuts are keyboard-only (ship mod U, wounds O), though panel-menu accessibility must be checked before claiming gamepad unreachable. Adapt inert controls or mark scope; retain actual playback, native map routing and glyph support. Avoid making multilingual support mandatory; the defect is misleading controls, not lack of every locale.

Settings validation is curated, not a strict arbitrary-input validator. A caller-injected NaN can survive to AccessibilitySettings and world-label scale; menus only cycle finite constants, so this is a low-severity API/fixture validation risk, not a demonstrated normal-menu defect. JsonNumber writes NaN as null (GdFloatFormat:73), which resets on next sanitize. Bus volumes likewise lack finite-number checks. Retain compatibility sanitization; add finite checks if extending settings inputs.
